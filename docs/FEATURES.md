# MyTube feature guide

Detailed behavior of MyTube 0.16.0. Start with the [project README](../README.md) for installation and the [development guide](DEVELOPMENT.md) for commands.

## TV interface

- Full-screen browsing with a compact sidebar in this order: Search, Home, Subscriptions, Library, separator, Live. Settings sits at the bottom. Moving D-pad focus to a menu item opens its page immediately; Enter is optional. Outlined search/home/subscription/bookmark/broadcast icons follow the supplied reference, and search history uses a clock with a return arrow.
- Compact pill-shaped Home search trigger and circular microphone button. The red rounded play mark and **MyTube** wordmark sit at the top right. Select the pill to open the search page. Speech recognition returns its phrase into the same search flow. The app uses the installed system recognizer and handles unavailable recognition without adding a login screen or recording audio itself.
- The sidebar starts with a local profile photo/name (User/U until configured); the obsolete footer text is removed. It reserves its actual expanded/collapsed width. It moves/resizes the three-column TV grid once per focus transition instead of covering it or animating all card measurements. Navigation buttons have fixed focus scale and safe inset space so their left borders remain visible.
- Right from the sidebar enters the active page, focusing the first video/channel or the search keyboard. Left from the first grid column returns to that page’s menu item. Search completion focuses the first result. Home retains its committed session while browsing sidebar pages. Explicitly starting a new Home session regenerates the mix; cancelled page preparation does not consume sources.
- Home initially samples five sources, with four distinct followed channels before topic searches where available. Each ten-video page balances channels across recency bands and shuffles ties; newer uploads within each channel retain priority. A single fresh channel cannot dominate just because the other channels posted earlier. Pagination appends stable batches and retains the existing prefix when returning from playback.
- Displayed Home/search/channel/related titles are resolved from YouTube's original oEmbed metadata with original player metadata as fallback. Requests run at most three at once, cancel when their work is cancelled, and cache up to 512 titles for 24 hours in memory. Only committed Home batches are resolved; related-title work runs after playback starts. Visible legacy history cards refresh their original titles through the browse model. If both original metadata sources are unavailable, the existing cached feed title remains available.
- Publication labels appear below each title beside the channel name: Today, 1 day ago, 2 days ago, 1 week ago, 1 month ago, and so on. Unavailable timestamps stay explicitly unknown; duration remains on the thumbnail. **Subscriptions** displays a grid of circular channel photos and names. Select a channel to open its feed; long-pressing a video retains channel/preferences actions.

Channel photos use the existing YouTube channel metadata: a maximum of three dedicated image-metadata requests run concurrently, with a bounded 64-channel, 24-hour in-memory cache shared with Home channel requests. The grid renders immediately; unavailable photos use a circular person placeholder without blocking navigation. No library schema change is required.

## Player and remote controls

The full-screen video uses Media3 with the default centered controller disabled. The bottom dock has a circular channel avatar and Subscribe on the left, bar-and-triangle previous/next glyphs and a geometrically centered play/pause glyph at the screen center, and local likes/dislikes, comments and Settings on the right. The avatar opens the channel feed. Previous/next traverse the current playback session; Next chooses a related video when there is no forward history. Playback starts with the dock hidden. After you reveal it, the dock hides after five seconds while playing and remains visible when paused.

- Select a video card to start playback immediately. Long-press a card for channel, subscription, save-example and other options.
- **Down:** video → focused progress bar → play/pause action row → related-video grid.
- **Up:** move through related-video rows, then return to the action row, progress bar and video. No return button is needed in the grid.
- With action buttons focused, press **Down** to open the related-video grid. Selecting a thumbnail starts that video in the same player.
- Left/Right seek ten seconds only with the progress bar focused. With video focus, Select toggles playback and Left/Right do nothing.
- The progress bar shows chapter divisions and red played portions when the video supplies chapters. The current chapter title appears beside the channel name and updates when seeking. Left/Right still seek ten seconds across chapter boundaries; videos without chapters keep a continuous timeline. Live streams do not acquire chapter divisions.
- Settings opens a right-side drawer with rounded Quality, Subtitles and Playback speed rows. Select a row for options; Back returns to the rows and then closes the drawer. No Close button is shown. Quality and speed persist on the device. Choosing quality/subtitles preserves position and play/pause state.
- Comments opens a right-side panel with rounded focusable cards, author avatars, publication labels, available like/reply counts and pinned markers. The total count appears when supplied by YouTube. Back closes it; no Close button or account composer is shown. The video uses the remaining space beside the panel. Comments are read-only and currently show the first response page.
- At natural video completion, **Up next** counts down ten real seconds before playing the first related recommendation. **Play next** starts immediately; **Cancel** or Down cancels autoplay and opens related videos. Any app-received interaction stops the timer; Up opens controls so you can replay. Leaving/backgrounding the player cancels the pending transition. No countdown interrupts an already open related grid, comments or settings, and no next video is scheduled when no recommendation is available.
- Back cancels Up next into related videos, closes the related/settings/comments panel, then hides controls, then leaves playback.
- Subscribe, like and dislike are **local MyTube preferences**. They do not change a Google/YouTube account or submit public reaction counts. Likes supply recommendation examples; dislikes exclude the video.

## Loading and search

Channel previews combine regular uploads and the Live tab, including broadcast replays, and deduplicate by video URL. An initially empty tab can defer its grid to continuation responses; MyTube follows up to three continuations per tab before reporting an unfinished-list error. This is a bounded recent preview, not the complete channel archive. Channel pages include watched videos with saved progress; Home recommendation exclusions do not hide them. Live-only feeds use the same deferred-grid handling and keep only entries identified as actively live. Regional playback restrictions still apply.

Sidebar highlight is updated before destination construction. Visited Home, Search, Subscriptions, Library, Live, Channel, Settings and Interests compositions are retained for the current activity, with separate scroll state. Only the active page is measured/placed; inactive pages are excluded from accessibility and focus entry. Search keeps its query/results/keyboard mode between visits. Retention is bounded to these eight route slots, including one reusable channel slot, and is released with the activity. It is an in-memory cache, not a disk layout cache.

Data loading belongs to a captured page, with an independent job per route. Leaving a page does not cancel its first load or Home pagination; completed data updates that page without switching the visible route. Library refreshes on entry, Live has a one-minute cache, opening a channel fetches that channel, and shared profile/subscription/interest/progress changes reach retained pages. Explicit preference changes invalidate Home/Live data for the next visit. New data can update a retained layout without rebuilding the page shell.

The initial Home/channel spinner is centered in the viewport. Home page preparation, including ranking/mixing, runs on a worker dispatcher. While the next ten videos are pending, loaded cards remain focusable and playable; the status footer is not a focus stop. Down on the last loaded row stays inside the grid on Home, channel pages, Library and Live; Left from the first column explicitly returns to the sidebar. Down at the last loaded row retains card focus until there are more videos, while Up/Left/Right continue to navigate existing cards.

Spinners indicate feed/page loading, search suggestions, video extraction/buffering and comment loading. Existing Home items remain usable while later pages load. Search shows text suggestions while typing, debounced by 300 ms. Only one autocomplete request runs at a time; intermediate queries are conflated and stale replies are discarded. Autocomplete uses an independent extractor path so a feed request cannot block it. Select a suggestion or SEARCH to search; results appear below the embedded keyboard, with focus on the first video. Search terms and partial queries are sent to YouTube for these suggestions; no Google sign-in is required.

Opening the top search pill shows a full-screen search page with a Back arrow. Focusing Search in the sidebar previews the same page beside the sidebar, with focus retained in the menu until Right enters the keyboard. In both layouts, recent searches/live text suggestions sit on the left, and an embedded D-pad keyboard sits beside them. The keyboard provides letters, numbers, Portuguese accents, delete, space and clear. Hardware keyboard typing is also accepted, without opening a system IME. Home recommendations appear below before submission; results replace that row after a search. More results append in ten-video batches using a search-owned continuation, independent of Home requests. Back returns to the previous browse page and its scroll position. The most recent 20 unique submitted phrases are stored locally; direct video URLs are omitted from this list. Settings can clear search history separately. The same phrases still go to YouTube to fetch results and autocomplete.

## Live and local profile

**Live** checks followed channels’ livestream tabs and searches saved interests, also considering channels from saved examples/recent browsing. At most three sources are checked concurrently. Results appear as they arrive and keep their existing order. Only explicit current live-stream metadata qualifies; recordings, explicit premieres/paid/member-only items and title-only “live” matches are excluded. An unknown access classification does not erase an explicit live-state flag; the player checks actual playback availability. LIVE badges identify the results. The page rechecks on entry when its retained result is more than one minute old or preferences changed; broadcasts may end after discovery. Partial source failures are shown without discarding successful results.

**Settings → Profile** stores a display name and photo on this device. Choose a local image or paste a public HTTPS image URL; a TV without a document picker can use the URL option. Imported photos are copied and sampled to at most about 1024 pixels on their longest edge. Name/photo/removal survive reopening; empty names use User and U. This display identity adds no Google login and does not alter subscriptions/history. No new storage/account permissions or library migration are needed.

## Saved interests and history

**Interests** manages topics/search phrases, followed channels and videos marked **Use for suggestions**. Home collects candidates from those sources and recent local history. Saved choices and history determine the candidate sources. Each new page filters watched/dismissed videos, favors fresh uploads and mixes channels; already displayed pages retain their order.

Thumbnails show a red progress strip along their bottom edge, with a full strip for a video that reached its actual playback end. Progress is attached to Home, channel, search, Library and related cards from the same local library snapshot; saved-player updates refresh browse cards after playback. Unknown-length/live videos do not show an invented percentage. Completed videos restart when explicitly played again; partially watched videos resume at their saved position. Clearing watch history clears these markers while retaining explicit preferences.

The local SQLite library stores completion flags, recent search phrases, watch history/resume positions, subscriptions, saved examples, interests and reactions. Clearing history retains explicit preferences. Additive schema migrations preserve existing library data. Uninstalling the app deletes its device-local data. A developer-owned, ignored `preferences.json` can import explicit channels/topics with `scripts/apply-preferences.sh`; it is not included in a fresh checkout or a backup of watch history.

YouTube metadata, search terms, streams and thumbnails still connect to YouTube and its infrastructure. There is no required Google login, analytics SDK, advertising SDK, cloud history service or automatic updater. This is not a promise of anonymity or uninterrupted extraction.


## Channel navigation, vertical results and audio

Opening a channel avatar enters its video feed directly. The Subscriptions label represents the channel’s parent destination; Right returns to the channel grid without selecting the subscription list. Back returns to Subscriptions. Search and Library show vertical three-column video grids on TV. Search loads more results when navigating near the last loaded rows, while existing cards remain usable. Up from later search rows stays in the grid; Up from its first row returns to the keyboard.

The player’s Audio language setting lists the separate tracks reported by NewPipe, marking original tracks. Each video starts with original-audio preference, independent of the TV’s language; another available language can be selected for the current video. Progressive playback explicitly pairs the chosen audio track with a video-only stream, so a high-bitrate dub cannot silently win over an identified original. Changes preserve position, pause/play state, speed and captions. The HLS fallback receives the identified preferred audio language. If upstream supplies no original-language identification or separately selectable track, the app cannot guarantee identification or manufacture alternate audio.

Search no longer has a results heading or Save interest action. The editor/history/keyboard panel collapses while a result has focus, giving the focused thumbnail, two-line title and metadata room to remain visible together. Up from the first result row restores the keyboard and its saved mode. Result rows align to the grid start as focus moves vertically. Topics remain editable through Settings → Manage interests & channels.
